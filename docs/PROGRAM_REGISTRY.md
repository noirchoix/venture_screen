# Program Registry Operating Policy

Program adapters are evidence snapshots, not timeless truth.

Each program entry must retain:

- `id`
- `name`
- `version`
- `captured_at`
- `source_url`
- current status / cohort notes
- criterion weights
- eligibility rules
- readiness thresholds

Hard rules should be used only when an official source makes the requirement explicit. Ambiguous or program-specific requirements should be warnings/applicability notes.

A cohort deadline should not erase underlying company/profile fit. Instead, mark the cohort unavailable and keep profile readiness separate.

Do not introduce an acceptance probability unless a calibrated evaluation dataset exists with both positive and negative outcomes, stable labels, sufficient sample size, and a methodology that can be audited.
